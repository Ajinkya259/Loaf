# Loaf — sprite contract

The interface between the Blender renderer and the macOS app. Everything else in this
project is cheap to change (the cat is generated by script; a rebuild is one command).
**This is the part that isn't.** Once the app ships and loads sprites by name, changing
any of it means touching both sides at once.

Derived from `ref/lil-cleo`, which already solved this for a shipped desktop pet.

---

## 1. Canvas

| | |
|---|---|
| Resolution | **640 × 512** |
| Format | PNG, RGBA, transparent background |
| Ortho scale | 2.6 world units across the 640px width |
| Camera | fixed at `(0, -9, 0.94)`, rotated `(90°, 0, 0)` — **never moves** |
| Ground line | world `z = 0`, which lands ~25px above the bottom edge |
| Anchor | **bottom-centre** |

Every state renders through these exact numbers (`SPRITE_*` in `blender/build_cat.py`).

**Why the camera never moves.** Ported from lil-cleo's `render_states.py`. A fixed camera
plus a character that rotates is the only way to guarantee identical scale and an
identical ground row across every state. Moving the camera per view lets both drift
silently, and the app anchors sprites bottom-centre — so any drift makes her visibly jump
or resize when she changes state. This project did move the camera per view early on;
that was the bug.

**Why landscape, unlike lil-cleo's 512×640.** Brick is a humanoid minifig, taller than
wide in every pose. A quadruped cat in profile is the opposite: 2.03 wide against 1.56
tall. Portrait cannot hold the standing profile without shrinking her so far that the
sitting states waste most of the frame.

---

## 2. Angles

**Profile is for locomotion. Front is for personality.** This is lil-cleo's rule and it
should be Loaf's:

| Angle | Used for |
|---|---|
| **Side** (profile, facing screen-right) | `side_idle`, `walk`, `run` — anything that travels |
| **Front** (facing camera) | every expressive/idle state: `sit`, `sleep`, `chonk`, `stressed`, `chill`, `wake` |

Two consequences:

- **Only right-facing side sprites are rendered.** The app mirrors them for leftward
  travel (`scaleEffect(x: facing)` in lil-cleo's `ImageCharacterView`). Never render a
  left-facing variant.
- **Don't render a side view of a non-locomotion state.** It isn't only redundant — the
  bell taper that makes a sit read lives in X, the width axis, which is exactly what a
  side camera can't see. An early side render of the sit pose read as a marmot.

---

## 3. Naming

```
sprites/<state>.png        a still
sprites/<state>1.png … N   a cycle, played back as a loop
```

The app counts frames by probing `<state>1`, `<state>2`, … until one is missing (capped
at 16). A state with no cycle falls back to the single still.

**Fallback chain:** `<state>` → `side_idle` → `hero`. So `side_idle.png` must always
exist — it's what any state with no art yet renders as. Ship it first, always.

Current sprites:

| File | State | Angle |
|---|---|---|
| `side_idle.png` | standing, neutral | side |
| `front_idle.png` | standing, neutral | front |
| `sit.png` | sitting | front |

## 3b. Committed look

Locked into `build_cat.py` — the exploration scripts are history, not source.

| | |
|---|---|
| Coat | `#E8944A` back, head, tail |
| Underside | `#F6F1E7` belly, bib, legs |
| Accent | `#2B2B33` socks, ear tips |
| Face | `#FBF8F4` / `#1A1A1E` only |
| Lighting | hard axis suns, no shadows, no specular |

**The face is monochrome and does not follow the coat.** White sclera, white muzzle
patch, white inner ear; black pupil, nose and mouth. It borrows nothing from the body,
so one face fits any colourway and she stays a single character. It is also the highest
contrast on the model, landing where you want the eye to go first.

**Eyes have a vertical slit pupil.** The most cat-specific feature available — no other
common pet has one. Also animatable: widen for startled, narrow for focused, no new
sprites needed.

**Lighting is flat, not studio.** Hard suns down the three axes with shadows and
specular off, so every face takes one flat value. Soft area lights smear a gradient
across each face and the model reads as generic 3D. No palette change substitutes for
this.

Alternate colourways live in `blender/explore_pattern.py`; swapping the three coat
constants is the whole change.

## 4. Face decals

Eyes exist as two separate sets of flat blocks — one glued to the head's front face, one
to each cheek. Only the set facing the camera is ever rendered; the other is `hide_render`
because a flat decal seen edge-on is a meaningless sliver.

- Side renders → cheek set only
- Front renders → front set only

`hide_render` is render-only, so **both sets show in the Blender viewport** and she
appears to have four eyes. That's why the builds put them in `Face_Front` / `Face_Cheek`
collections — toggle the monitor icon in the outliner.

## 5. Reviewing

Sprites ship with alpha, but Loaf is a **white** cat, so a raw sprite composited over
a white background is a blank rectangle. Never review the files in `sprites/` directly.

```bash
blender/make_previews.sh     # composites everything over grey into previews/
```

That also writes `previews/contact_sheet.png` — all states side by side, which is how you
catch a state drifting out of sync with the others. It caught the standing build keeping
tall rabbit ears after only the sitting build had been fixed.

---

## 6. Rebuilding

```bash
blender/build_all.sh        # both builds + previews. Use this, not one script alone.
```

Running a single build script is how the two drifted apart twice: once the standing cat
kept rabbit ears after only the sit was fixed, and once the sit was deleted outright by
a clean that only re-ran the stander.

Each script wipes the scene and rebuilds from nothing, so geometry, rig and palette
changes are all one command. `build_cat_sit.py` imports the palette and the camera rig
from `build_cat.py` — change a colour in one place only.

**Back up first.** Nothing in this directory is under git, and `save_as_mainfile` rotates
`cat.blend` into `cat.blend1`, which destroys the previous backup.
